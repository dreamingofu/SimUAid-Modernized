# ECE 3441 Lab 3 — SimUaid acceptance case

This document records how SimUaid Modernized covers the software portions of
ECE 3441 Lab 3 ("The Digital Design Process with SimUAid II"). It uses one
assigned function as the acceptance case. Where the lab handout mentions
LogicAid, use SimUaid's **Tools → Boolean Expression / Truth Table…** dialog.

Assigned function:

```
F = BCD + ABCD' + C'D + AB'D        inputs A, B, C, D (A is the MSB)
```

## Part 1 — Minterm expansion

Expand each product term over the variables it is missing. X + X' = 1.

| Term    | Expansion                       | Minterms |
|---------|---------------------------------|----------|
| BCD     | A'BCD + ABCD                    | 7, 15    |
| ABCD'   | ABCD'                           | 14       |
| C'D     | A'B'C'D + A'BC'D + AB'C'D + ABC'D | 1, 5, 9, 13 |
| AB'D    | AB'C'D + AB'CD                  | 9, 11    |

Minterm 9 appears twice; X + X = X (idempotence) keeps it once.

```
F = Σm(1, 5, 7, 9, 11, 13, 14, 15)          8 minterms

F = A'B'C'D + A'BC'D + A'BCD + AB'C'D + AB'CD + ABC'D + ABCD' + ABCD
```

## Part 2 — Minimum SOP

K-map prime implicants, all of them essential:

| Prime implicant | Covers         | Essential because only it covers |
|-----------------|----------------|----------------------------------|
| C'D             | 1, 5, 9, 13    | m1  |
| BD              | 5, 7, 13, 15   | m7  |
| AD              | 9, 11, 13, 15  | m11 |
| ABC             | 14, 15         | m14 |

```
F = AD + BD + C'D + ABC          4 terms, 9 literals (unique minimum)
```

An algebraic cross-check (students still have to show their own steps):

1. C'D + BCD = D(C' + BC) = D(C' + B) = C'D + BD  — distributive law, then X' + XY = X' + Y.
2. AB'D + BD = D(AB' + B) = D(A + B) = AD + BD  — same simplification theorem.
3. AD + ABCD' = A(D + D'BC) = A(D + BC) = AD + ABC  — same theorem with X = D.
4. Collect: F = AD + BD + C'D + ABC.

The dialog reports the same result: minimum SOP `F = AD + BD + C'D + ABC`.
Its minimizer is exact for up to four inputs (fewest terms, then fewest
literals; ties broken by a fixed term order), and is unit-tested against brute
force.

## Part 3 — Circuit, stimulus and timing diagram

### Workflow in SimUaid

1. **Tools → Boolean Expression / Truth Table…**
2. Inputs: `A B C D`. Expression: `BCD + ABCD' + C'D + AB'D`. An `F =` prefix
   is optional. Adjacent letters are AND, `+` is OR, `'` (or `’`/`′`) after a
   letter or `)` is NOT, and parentheses group. A typing mistake shows a message
   with its column number.
3. Read the minterms, standard SOP, minimum SOP and 16-row truth table. Use
   **Copy report** to paste them as text, or **Print report…** to print them.
4. Click **Create circuit…**. If the current circuit has unsaved changes, the
   usual Save / Don't Save / Cancel prompt appears first; Cancel keeps the
   current circuit. The new circuit opens as an unsaved document.
5. **Simulate → Go** runs 0–1600 ns.
6. **Window → Open/Close Timing Diagram**. Pick **100 ns/div** (one division
   per input combination) or **Fit run** (the whole run in the panel). The
   cursor line reads times in ns; the end of the run is marked `end 1600 ns`.
7. The timing panel's 🖶 button prints the whole run with the A, B, C, D, F
   names, ns tick labels and the 1600 ns endpoint. **File → Print…** prints the
   schematic.
8. **File → Save As…** keeps the circuit, its stimuli and its probes in a `.ckt`
   file. Reopening restores all of them.

`samples/lab3-assigned.ckt` is the circuit from step 4, generated by the same
production builder (`src/renderer/src/boolean/sopCircuit.ts`).

### Generated circuit

- Four INPUT_SIGNAL sources labeled A, B, C, D. Each pin label matches its
  device label.
- One NOT gate (`C'`). AND gates `AD`, `BD`, `C'D` (2-input) and `ABC`
  (3-input). One 4-input OR.
- Probes in timing-diagram order: A, B, C, D, F.
- Every connection is a drawn wire, and a dot marks each junction. Only the
  input sources carry pin labels, so no logic depends on named-net shortcuts.
  The vertical rails carry A, B, C, C', D. True rails continue below the gates
  to the input probes.
- Every part has the default 1 ns propagation delay. Simulation time is 1600 ns.
- All four inputs and their stimuli are always generated, even when the
  minimum SOP drops a variable.

### Simulation versus truth table (real engine)

Waveforms recorded by the simulation engine for `samples/lab3-assigned.ckt`
after one **Go** (time ns : value at each change):

```
A  0:0 800:1
B  0:0 400:1 800:0 1200:1
C  0:0 200:1 400:0 600:1 800:0 1000:1 1200:0 1400:1
D  0:0 100:1 200:0 300:1 400:0 500:1 600:0 700:1 800:0 900:1 1000:0 1100:1 1200:0 1300:1 1400:0 1500:1
F  0:0 102:1 202:0 502:1 602:0 702:1 802:0 902:1 1002:0 1102:1 1202:0 1302:1
```

Sampling each interval at its midpoint (50, 150, …, 1550 ns) gives
F = `0100010101010111`, which matches all 16 rows of the truth table. At the
1600 ns endpoint, A B C D F = 1 1 1 1 1. The simulated output matches the
theoretical truth table.

The integration test `src/renderer/src/boolean/lab3Acceptance.test.ts` checks
this. It reads the saved `.ckt` file, parses it with the production
deserializer, runs the real `Simulator`, and checks A/B/C/D/F in all 16
intervals and at 1600 ns. The expected F column is hard-coded from the K-map
above, not computed by the expression parser. The test also checks that the
saved file equals the production builder's output, and that it survives a
save/reopen round trip.

### Why sample mid-interval: propagation delay

Each gate takes 1 ns. An input change reaches F through at most three gates
(NOT → AND → OR), so F settles no later than 3 ns after each 100 ns boundary.
In this run, every F change happens 2 ns after a boundary. The changes that
matter all come through D, which feeds the AND gates directly (AND 1 ns + OR
1 ns). For example, F rises at 102 ns, not 100 ns. The acceptance test checks
that every F change happens within 3 ns of a boundary.

So compare outputs with the truth table at the middle of each interval, or
anywhere more than 3 ns after a boundary. Reading exactly at a boundary shows
the previous row's output.

Other functions, or other gate arrangements, can produce a brief hazard glitch
of 1–2 ns at some transitions. For example, the unsimplified original network
glitches at 1402–1403 ns. Glitches like this are real timing behavior of the
gate delays, so the simulator does not remove them. The settled mid-interval
values are what to compare with the truth table.

## Scope and limits

- Covered: Parts 1–3 software deliverables (minterm list and count, standard
  SOP, minimum SOP, truth table, schematic, 100 ns stimulus, timing diagram,
  simulation-versus-truth-table comparison).
- Not covered: Part 4 physical breadboard, DIP switches, resistor selection,
  LED demo and video. Also not covered: LTspice, and the report write-up. The
  hand algebra with named theorems (deliverable 3) is the student's own work;
  the dialog checks the result only.
- Expressions: 1–4 single-letter inputs, case-insensitive. Up to 512 characters,
  16 nested parentheses and 400 operations. Prefix NOT (`~A`, `!A`) is rejected
  with a hint to use `A'`. Don't-care terms and product-of-sums output are not
  supported.
- The app has no undo. Create circuit always opens a new unsaved document,
  after the standard unsaved-changes prompt. It never merges into or
  overwrites the open circuit silently.
- The timing panel offers 1–1000 ns/div and Fit run. It caps its canvas at
  16,000 CSS px wide and at about 16 M device pixels. Scales that would exceed
  the cap are disabled for that run.
